# 把你要处理的文档丢进这个文件夹

然后运行：

```
run.cmd inbox
```

它们会被归一化后存进 `data/raw/`，和 RSS 抓来的东西混在一起，
`run.cmd sample` 抽样本时不会区分来源。

---

## 为什么会有这个文件夹

**因为实测发现，从 RSS 抓全文这条路在你的环境下不成立。**

用你自己的网络实测的结果：

| 源 | 它实际给了什么 | 能做摘要评估吗 |
|---|---|---|
| 量子位 | 17–18 字的一句话摘要 | 不能 |
| InfoQ 中文 | **7 个字** | 不能 |
| Google AI Blog | 22–68 字，而且间歇性 SSL 失败 | 不能 |
| DeepMind | 第一次成功，第二次 SSL 失败 | 不稳定 |
| MIT Technology Review | 全文 6420–27014 字 | 能 |

大多数 RSS 的设计目的就是**让你决定要不要点进去**，它不负责给你全文。
而"摘要"这个任务需要正文。**数据里没有正文，换多贵的模型都摘要不出来。**

这就是我在架构蓝图里写的那条边界的一个真实案例：

> "效果不好"通常不是模型层的问题，是数据层的问题。

## 修法不是换源，是解耦

```
生产线（信息雷达）：RSS 负责【发现】—— 标题 + 链接 + 一句话摘要。
                    这就够了，它只需要帮你决定"这篇要不要看"。

评估集：需要的是【你有全文的、你真正关心的】文档。
        它从哪来不重要。
```

把它们绑在一起，是这个项目暴露出的第一个真实架构错误。

## 支持的格式

| 后缀 | 说明 |
|---|---|
| `.md` | 第一行或第一个 `#` 开头的行当标题，其余当正文 |
| `.txt` | 同上 |
| `.html` | 网页另存为，会自动去掉标签 |
| `.json` | 需要含 `title` 和 `body` 两个字段 |

以 `_` 开头的文件会被忽略（所以本文件不会被当成文档导入）。

## 评估集该放什么

不要放"随便找的 20 篇"。放**你本来就会认真读的那 20 篇**。

原因很实际：你标真值的时候要读完全文才能判断"模型有没有漏要点、有没有编事实"。
如果文档你自己都不在乎，你不会有耐心认真标；而标得敷衍，整个评估就是假的。
