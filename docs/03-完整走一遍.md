# 完整走一遍：从零到第一个基线

> 这份文档是**一条命令一条命令地走**，每一步都附上「你应该看到的样子」。
> 这样你能自己判断是走对了，还是卡住了 —— 不需要问我。
>
> 全程估计 40 分钟，其中 30 分钟是标注（唯一不能省的部分）。

所有命令都在这个目录下运行。

## 第 0 步 · 确认地基

```cmd
cd C:\Users\谢安豪\Documents\deepseek-harness\default-workspace\info-radar
run.cmd selftest
run.cmd mocktest
```

**你应该看到：最后都是「全部通过」：**

```
  全部通过  N / N
  全部通过  N / N
```

> **`N` 会变，不要去对数字。** 这个项目一边长，自检项数一边增加 ——
> 上面写 `N` 而不是具体数字，就是因为写具体数字会让这份文档每隔几天就变成假警报。
>
> **唯一要确认的是：没有以 `[!!]` 开头的行。** 有它才说明真的出问题了。
>
> （我特意为这件事加了一条自检：文档里再出现写死的项数，自检会直接报出来。）

这两个命令**不联网、不花钱、不要密钥**。如果它们没过，后面所有事都不用做 ——
先修地基。

> 为什么先跑这两个：把「代码对不对」和「密钥通不通」分开排查。
> 混在一起排查，你会花大量时间在一个根本不相干的地方。

## 第 1 步 · 看数据（已经替你取好了）

```cmd
run.cmd sources
```

**你应该看到**（数字会有小波动）：

```
  信息源检查（真实抓取）　可用正文线：200 字

  [OK] 极客公园
       条目 30　【可用 30】　正文 最短1536 中位4549 最长6401　2.7s
       全文源，可用
  ...
  【本轮共可入库 118 篇可用正文】
  够做评估集了。跑：run.cmd collect
```

**这一步要看的是「可用」那两个字后面的数字，不是「条目」。**

- `条目 30　可用 0` = 这个源只给一句话摘要，**一条都用不上**
- `条目 30　可用 30` = 全文源，能用

如果你以后自己加源，加完一定先跑这个命令。一个死掉的源不会报错，
它只是安静地返回零条 —— 然后你会以为"今天没新闻"。

## 第 2 步 · 标注（唯一不能省的部分）

### 最省事的做法：双击桌面上的【1-开始标注】

**它已经在你桌面上了。** 直接双击。

会弹出一个黑窗口，它开始一条一条问你。

> 那个快捷方式指向 `info-radar\开始标注.cmd`。不想要就删掉它，不影响任何东西。
> 另外桌面上还有【2-看下一步】—— 任何时候不知道做什么，双击它。

### 或者，自己找文件

按 `Win + R`，粘进这一行回车：

```
C:\Users\谢安豪\Documents\deepseek-harness\default-workspace\info-radar
```

找到 `开始标注.cmd`，双击。

### 或者，用命令行

```cmd
run.cmd wizard
```

三种方式效果完全一样。

它会一条一条问你。**你只需要按数字。**

**你应该看到**（这是真实的第 1 条的样子）：

```
==================================================================
  标注向导　共 20 条，已填 0 条，还剩 20 条
==================================================================

  一次问一条。看懂了就按一个数字，不用打中文。
  随时按 Ctrl+C 退出 —— 已经答完的会立刻存盘，下次接着来。


------------------------------------------------------------------
  【第 1 条 / 还剩 20 条】

  AI disqualification yields new Nikon Small World in Motion winner
  来源：Ars Technica　·　2105 字

  Credit: Nguyen Nam Nhat. Last month we covered the winner of Nikon's
  Small World in Motion video: Ning Xu of Tsinghua University in China…

  （开头只显示这么多。想看全文就按 m）

  它属于哪一类？
    1. 产品发布
    2. 模型与技术
    3. 融资并购
    4. 政策监管

    7. 观点与分析
    8. 其他
    0. 拿不准（记为 ?，不计入准确率）

  请输入数字后回车：
```

你读完这条新闻，在键盘上按一个数字，回车。
然后它会问"有多重要"，你再按一个 `1`–`5` 的数字。
**然后自动跳到下一条。**

### 你会用到的几个键

| 按什么 | 会发生什么 |
|---|---|
| `1`–`8` | 选分类 |
| `0` | 拿不准（记为 `?`，不计入准确率） |
| `1`–`5` | 选重要性（`5` 最重要，`1` 最不重要） |
| `m` | 看这条的全文（在问分类的时候按） |
| `q` | 退出（已答的存着） |
| `Ctrl+C` | 退出（已答的也存着） |

**随时可以停下来。** 每答完一条它立刻存盘。今天做 5 条、明天接着做 10 条，都行 ——
再跑 `run.cmd wizard` 会自动从没答完的地方继续。

### 没有标准答案

**按你自己的兴趣写。**

同一条新闻，做 AI 的人可能觉得"跟我直接相关"打 4 分，
做手机的人可能觉得"跟我无关"打 1 分。**两个都对** ——
这是"你的"工作系统，标准是你自己定的。

> **为什么必须你自己写那 20 条**
>
> 因为如果让我（AI）来写标准答案，那标准答案就是 AI 自己想的，
> 拿它去考 AI —— 永远满分，永远没意义。
>
> 这不是我推责任，是这件事能不能成立的前提。
> 你的这 20 个判断，就是后面所有数字的尺子。

### 如果你不想用向导

也可以手工填。先看 `eval/worksheet-lite.md`（10KB，标题+开头），
拿不准的再去 `eval/worksheet.md`（118KB，全文版）里搜它的 id。
然后把 `<id> | 分类 | 重要性` 写进 `eval/labels.txt`。

**但向导省掉了"在两个文件之间对 20 个编号"这件事，建议先用它。**

3. **重要性不要全给 3。** 那样这一列就没有信息量了，等于没标。

**填完之后：**

```cmd
run.cmd labels
```

应该显示 `100%`、`已标注 20`、`还没填 0`。

```cmd
run.cmd compile
```

**你应该看到：**

```
  已写入 eval/eval_set.jsonl
    可评分样本  20 条
    分类分布    模型与技术 7，产品发布 5，...

  下一步：先填 config/providers.json 的单价，然后
    run.cmd eval -Limit 3
    run.cmd eval
```

### 如果 `compile` 报了这些问题，先处理它们

```
  * 样本只有 8 条。少于 10 条时，准确率的一个样本就值 10 个百分点，数字会非常不可靠。
  * 分类严重不均衡：12/20 条都是「模型与技术」（60%）。
    这种评估集测不出区分度 —— 一个永远回答「模型与技术」的模型也能拿到 60%。
  * 重要性全都是 3。这一列没有信息量了，等于没标。
```

**这三条不是错误，是三个会让你后面那个数字失去意义的陷阱。**
特别是第二条：辛苦标了 20 条、拿到 85% 准确率，感觉很好 ——
直到你意识到"永远猜最多的那一类"能拿到 60%。

## 第 6 步 · 跑一次生产流程

```cmd
run.cmd pipeline
run.cmd digest
```

`digest` 会生成两份东西：

- `out/digests/<时间戳>.md` —— 日报，**标注着「未审核」**
- `out/review/<时间戳>.txt` —— 审核表，给你填的

打开审核表，格式是：

```
<id> | 收录 | 分类 | 重要性
```

**收录列留空就是通过；分类和重要性已经填了模型的判断，你不改就是认可。**

改完：

```cmd
run.cmd review --apply <时间戳>
```

**你应该看到：**

```
  审核条目   20
  不收录     3
  分类改判   5
  重要性改判 4

  模型分类被你改掉了 5/20 = 25%
  这个数字就是它在真实流量上的准确率 —— 不需要额外跑一次评估。

  回流评估集 17 条新真值
  评估集现在有 37 条样本。
```

> **这是整套系统里唯一一处「它会自己变强」的地方。**
> 你今天人工纠正的每一条，都变成明天的真值样本。
> 评估集从 20 条涨到 200 条时，你对系统的信任就不再是感觉，而是统计。

## 第 7 步 · 交给它自己跑

```cmd
run.cmd daily
```

它按顺序跑 采集 → 处理 → 日报。**默认遇到失败就停** ——
因为一个在失败之后继续产出的流水线，它的产出和有成功时长得一模一样。

然后：

```cmd
run.cmd health
```

```
  任务              连续失败  上次成功        最近结果
  ----------------------------------------------------------------
    collect         0     10-11 21:30   新增 12 条，成功源 6/6
    digest          0     10-11 21:31   日报 20261011-213100.md（12 条可用）
    pipeline        0     10-11 21:31   处理 12/12 条，成功 12

  「今天没新闻」和「流程三周前就死了」在表面上完全一样。
  这张表是你区分它们的唯一依据。
```

**最后一步：把它挂到 Windows 计划任务上，每天跑一次 `run.cmd daily`。**
连续失败 3 次会写 `out/ALERT.md` 并把退出码设成非零。

## 怎么知道你真的内化了

能回答下面这七个问题，说明你拿到的是**这套结构**，而不是这个项目：

1. **你的评估集里有多少条？手工标注和审核回流各多少？**
   → `run.cmd review --stats`

2. **你的模型分类准确率是多少？在什么模型、什么成本下？**
   → `run.cmd status`

3. **把 `config/task.json` 的 `prompt.few_shot` 加三条示例，准确率变成多少？**
   先预测，再验证，然后写一句话结论进 `CHANGELOG.md`。
   （提示：这是"上下文比提示词重要"的实证。你会看到它的提升幅度远大于反复推敲措辞。）

4. **把 `max_body_chars` 从 3000 改成 1000，成本和准确率各会怎么变？**
   **先写下你的预测**，再改、再跑、再对比。预测错了比预测对了更有价值。

5. **你的 6 个源里，哪个最慢？哪个可用率最低？**
   → `run.cmd sources`

6. **如果连续三天没有新内容，`run.cmd health` 会显示什么？**
   → 应该显示「跳过」，**不是**「失败」。为什么这个区分很重要？

7. **换一个完全不同的任务**（比如"每周把销售 Excel 整理成汇报材料"），
   **哪几层要重写、哪几层原样不动？**
   → 回到 [`00-架构蓝图.md`](00-架构蓝图.md) 第五节的表对照。

第 7 题是真正的检验。**能一眼看出哪些是地基、哪些是插件，你才算真的拿到了这套结构。**

## 卡住了怎么办

| 症状 | 先跑这个 |
|---|---|
| 不知道现在该做什么 | `run.cmd status` |
| 报错看不懂 | `run.cmd selftest`（确认不是代码问题） |
| 密钥相关报错 | `run.cmd probe` |
| 源抓不到东西 | `run.cmd sources` |
| 不知道它最近跑得怎么样 | `run.cmd health` |
| 花了多少钱 | `run.cmd ledger` |

**一个通用的排查顺序：**
`selftest` → `mocktest` → `status` → `health` → 具体那一步。
从前到后，是从"代码对不对"到"这一次具体发生了什么"。
